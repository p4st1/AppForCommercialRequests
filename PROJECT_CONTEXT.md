# PROJECT_CONTEXT.md

## 1. Общее описание проекта

**Название проекта:** `AppForCommercialRequests` (рабочее имя в пользовательской среде: `MyApp`).

**Краткое описание:**  
`AppForCommercialRequests` — desktop-приложение на Python (`PySide6`) для подготовки коммерческих предложений (КП), расчета ценовой части, ведения клиентской базы и хранения истории документов. Система загружает исходные прайс-таблицы поставщика (CSV/XLS/XLSX), автоматически применяет формулы (логистика, таможня, наценка, НДС, сроки), формирует финальные документы и фиксирует результат в истории.

Приложение ориентировано на быстрый цикл: «получил таблицу поставщика → рассчитал → собрал КП → экспортировал документ». Архитектурно это локальное монолитное приложение с SQLite, файловыми шаблонами (`DOCX`, `XLSX`) и конфигурацией в JSON.

**Основная цель системы:**  
Сократить время подготовки коммерческих предложений и снизить количество ошибок в расчетах и оформлении.

**Какие проблемы решает:**
- Ручной и медленный расчет КП в Excel/Word.
- Разрозненное хранение клиентов и условий работы.
- Ошибки в формулах и валютных суммах при копировании данных.
- Отсутствие единой истории созданных предложений.
- Нестабильный формат коммерческих документов между менеджерами.

## 2. Целевая аудитория

**Кто пользователи:**
- Менеджеры по продажам B2B.
- Тендерные/закупочные специалисты.
- Коммерческий отдел и бэк-офис, готовящий ответы на заявки.

**Их боли:**
- Много однотипной ручной работы.
- Ошибки в цифрах и сроках при дедлайнах.
- Невозможно быстро повторить прошлое КП.
- Дубли клиентов и потеря контекста по заказчикам.

**Как продукт им помогает:**
- Автоматизирует пересчет по формульной модели.
- Стандартизирует структуру КП через шаблоны.
- Дает централизованную базу клиентов и проверку дублей.
- Хранит историю документов с возможностью повторного создания.

## 3. Основной функционал

- **Генерация коммерческих предложений**
  - Импорт строк поставщика из CSV/XLS/XLSX.
  - Автоматический расчет полей: логистика, таможня, цена реализации, НДС, сроки.
  - Генерация DOCX по выбранному шаблону.
- **Шаблоны**
  - Поддержка полного и сокращенного шаблона (`template.docx`, `template_short.docx`).
  - Шаблон расчетной таблицы (`template.xlsx`) для выгрузки расчетов.
  - Плейсхолдеры вида `{{...}}` и `<<...>>`.
- **Персонализация**
  - Данные заказчика (компания, ФИО, должность, условия).
  - Условия оплаты, гарантия, производитель, сроки.
  - Автоподстановка номера заявки/КП и дат.
- **Экспорт (PDF / DOCX / HTML)**
  - `DOCX`: поддерживается в MVP (основной формат КП).
  - `XLSX`: поддерживается в MVP (расчетная часть).
  - `PDF`: не реализован нативно в MVP, планируется через отдельный модуль конвертации.
  - `HTML`: не реализован в MVP, планируется как формат предпросмотра/веб-экспорта.
- **Интеграции**
  - Локальный импорт CSV/XLS/XLSX.
  - Проверка версии приложения через GitHub release metadata.
- **Управление клиентами**
  - CRUD по заказчикам (создание, редактирование, удаление).
  - Поиск и фильтрация.
  - Поиск потенциальных дублей по компании + email/телефону/ФИО.
  - Импорт/экспорт клиентской БД.
- **История предложений**
  - События создания DOCX и экспорта Excel в таблице `offers`.
  - Хранение сумм, количества позиций, пути к файлу, payload.
  - Повторное создание КП из истории.

## 4. User Flow (как пользователь работает с системой)

1. **Пользователь заходит**  
   Запускает `run.py`; приложение инициализирует пользовательские файлы (`config.json`, `database.db`, `variables.json`, шаблоны).
2. **Создает новое КП**  
   В главном окне загружает файл поставщика (CSV/XLS/XLSX).
3. **Вводит данные клиента**  
   Выбирает или создает заказчика в модуле клиентов, заполняет контакты и условия.
4. **Выбирает шаблон**  
   В форме создания документа выбирает вариант шаблона (полный/сокращенный), условия оплаты и дополнительные параметры.
5. **Генерирует документ**  
   Система выполняет расчеты, подставляет переменные в шаблон и формирует DOCX.
6. **Редактирует**  
   При необходимости корректирует строки, формулы, параметры (логистика/наценка/таможня/срок).
7. **Экспортирует / отправляет**  
   Сохраняет DOCX/XLSX в рабочую папку, после чего отправляет клиенту внешними каналами (почта/мессенджер).

## 5. Архитектура системы

### Frontend
- Технология: `PySide6` (Qt desktop GUI).
- Ключевые окна:
  - Главное окно (`main.py`): таблица, формулы, вкладки «Итог», «История», «Обновления».
  - Окно создания документа (`createDocument.py`).
  - Окна клиентов (`customers.py`, `addNewCustomer.py`).
  - Окно параметров формул (`params.py`).
  - Окно настроек (`settings.py`).

### Backend
- Локальный Python-монолит без отдельного серверного процесса.
- Бизнес-логика:
  - Импорт и парсинг таблиц (`main.py`).
  - Расчеты и валидации (`main.py`, `tools.py`).
  - Генерация DOCX/XLSX (`create.py`).
  - Работа с БД (`database.py`).

### API
- Внешний HTTP API в MVP отсутствует.
- Внутренний API: вызовы Python-классов/методов и передача структурированных payload.
- Де-факто контракты:
  - Табличные строки для экспорта.
  - JSON-представление истории (`payload_json`).
  - JSON-конфиг и JSON-параметры переменных.

### Хранение данных
- `SQLite`:
  - `customers` — карточки заказчиков.
  - `offers` — история созданий/экспортов.
- `JSON`:
  - `config.json` — пользовательские настройки.
  - `variables.json` — именованные параметры формул (например НДС).
  - `version.json` — локальная версия и release metadata.
- Файлы шаблонов:
  - `template.docx`, `template_short.docx`, `template.xlsx`.
- Логи:
  - `logs.log`/`logs.txt`.

### AI-часть (Codex / LLM)
- **Текущее состояние MVP:** runtime-LLM в приложении не является обязательным компонентом; генерация документа выполняется шаблонно-детерминированно.
- **Роль Codex/LLM в проекте:**
  - Помощь разработке (изменение логики, шаблонов, тестов).
  - Подготовка/улучшение текстовых блоков КП (как опциональный слой).
  - Контроль качества формулировок и персонализации.
- **Целевое расширение:** подключаемый AI-модуль для генерации narrative-блоков КП на основе структурированных входных данных.

## 7. Формат генерации коммерческого предложения

### Блоки документа
- Заголовок (номер КП, дата, реквизиты поставщика).
- Блок адресата (компания клиента, контактное лицо, должность).
- Оффер/вводный абзац.
- Таблица позиций:
  - №
  - Наименование
  - Каталожный номер
  - Ед. изм.
  - Кол-во
  - Цена за ед. без НДС
  - Итого без НДС
  - Итого с НДС
  - Срок поставки
- Коммерческие условия (оплата, гарантия, производитель, условия поставки).
- Итого (числом и прописью).
- Подпись/контакты.

### Как формируется текст
- Структурные данные берутся из:
  - таблицы товаров;
  - карточки клиента;
  - формы дополнительных параметров;
  - системных параметров и дат.
- Текст в шаблоне собирается через замену токенов `{{...}}` и `<<...>>`.
- Числовые блоки форматируются с учетом валюты и округления.

### Какие переменные используются
- **Клиентские:** `company`, `name`, `surname`, `post`, `conditions`, `gender`.
- **Коммерческие:** `app_num` (номер заявки), `Garanty_period`, `Pay_cond`, `Producer`, `MinDays`.
- **Формульные:** `Amount`, `UnitPrice`, `TotalPrice`, `Logistic`, `Custom`, `Markup`, `VAT`, `SupplierTerm`, `TermDelivery`.
- **Шаблонные токены (пример):** `{{num}}`, `{{now}}`, `{{Total_wo_text}}`, `<<TOTAL_WO>>`, `<<CLIENT_COMPANY>>`.

## 8. Логика работы AI

### Что делает Codex
- Формирует/улучшает текстовые блоки КП по входным данным.
- Приводит стиль под бизнес-контекст и тон общения с клиентом.
- Валидирует логическую согласованность текста с расчетами.
- Помогает сопровождать кодовую базу (рефакторинг, тесты, архитектурные изменения).

### Какие входные данные получает
- Тип бизнеса и продукт/услуга.
- Профиль клиента и его потребности.
- Таблица товаров и рассчитанные суммы.
- Шаблон документа и требования к стилю.
- Ограничения: формальность, длина, обязательные блоки.

### Какой результат должен выдавать
- Готовый структурированный текст КП (или JSON-блоки для вставки в шаблон).
- Без противоречий с цифрами и сроками.
- С персонализацией под клиента.

### Требования к качеству текста
- Деловой, ясный стиль без «воды».
- Конкретные выгоды и следующий шаг для клиента.
- Отсутствие неподтвержденных обещаний.
- Грамотность и единый терминологический стиль.

## 9. Примеры входа и выхода

### Input
- `тип бизнеса`: Поставка промышленного электрооборудования.
- `продукт`: Частотные преобразователи и шкафы управления.
- `клиент`: ООО «ЭнергоТех», контакт — Петров А.А., задача — закрыть потребность по проекту модернизации.

```json

  "business_type": "B2B поставка оборудования",
  "product": "Частотные преобразователи",
  "client": {
    "company": "ООО ЭнергоТех",
```

## 11. Ограничения и допущения

### Что система НЕ делает (MVP)
- Не выполняет массовую рассылку КП клиентам.
- Не имеет полноценного веб-интерфейса и многопользовательской совместной работы.
- Не хранит версионность шаблонов как отдельные сущности в БД.
- Не поддерживает нативный экспорт PDF/HTML.

### Ограничения MVP
- Смешанная валюта в одной таблице блокирует экспорт DOCX/XLSX.
- Нет внешнего CRM/ERP-интеграционного контура из коробки.
- Текст КП в основном формируется по шаблонам; AI-генерация является опциональным расширением.
- Локальное хранение предполагает ответственность пользователя за резервное копирование.
